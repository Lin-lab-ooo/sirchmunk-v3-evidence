# Sirchmunk V3：预算约束下的图证据选择

[English](README.md) · [完整结果](docs/results.md) · [数学与伪代码](docs/algorithm.md) · [复现说明](docs/reproduction.md)

目标是在需要跨文档推理时，更完整地选取相关来源，并量化时间与费用代价。V3通过有界标题连接和候选集合选择接入固定版本Sirchmunk DEEP，保留模型分析、真实检索、综合及纠正的自适应流程。这是独立研究扩展，不是魔搭官方项目。

## 最新数据与两批合并结果

两批共80道不同题，已核对来源ID和规范化问题哈希无交集。合并仅作描述性统计：较早一批使用1600段共享语料，最新一批使用4000段，不能称为同一个80题同配置实验。

按全部80题计划分母，保留V3的一次单题请求上限中断，答案计零分：

| 指标 | 适配原生DEEP | V3 |
|---|---:|---:|
| 答案EM | 40/80，50.0% | 42/80，52.5% |
| 答案F1 | 71.56% | 72.02% |
| 完整支持来源读取 | 43/80，53.75% | 57/80，71.25% |
| 总token，包含中断 | 1,165,698 | 954,562 |
| 模型请求 | 676 | 640 |
| 平均问答耗时 | 82.22秒 | 83.49秒 |
| 已知token峰价估算 | 2.834766元 | 2.397362元 |

观察到V3净多对2题、token减少18.1%、耗时略增。逐题胜4、负2，探索性精确配对检验p=0.6875，不能宣称已证明整体领先。峰价估算不是实际账单。

两组都完成的配对子集为79题，EM为40/79与42/79，token减少19.3%；其费用不包含未完成配对的两行。报告同时保留79题与80题分母，不能混用。

最新一批单独看：40题计划分母EM为19/40与20/40；39题完整配对EM为19/39与20/39、完整来源为20/39与28/39。此39题V3 token少17.3%，耗时高1.2%。完整来源命中表示读取覆盖，不代表所有关系支持答案。

## 本地验证

Python 3.12以上，核心测试与统计复算只需标准库：

```powershell
python -B tools/run_core_tests.py
python -B scripts/recompute_results.py --check
```

已经准备好固定上游、模型和工具的运行环境时，使用该环境的Python：

```powershell
python -B tools/verify_runtime.py --project "准备好的运行时目录"
python -B tools/offline_native_smoke.py --project "准备好的运行时目录"
```

原生示例执行真正的本地工具检索和自适应模型阶段，模型响应由虚构脚本提供；不输入密钥、不联网、不读私人账本、不安装依赖。它验证机制，而不是重测付费准确率。

固定上游提交为 `b314e11fcea87cf8146b2844cf2f991208c021d9`。历史付费模型为 `deepseek-flash`、非思考、每次最多输出512 tokens；每题每组独立冷启动，题内仍有连续自适应上下文。

## 结论边界

当前更扎实的观察是来源覆盖提高、token减少；EM只有小幅优势，时间没有稳定收益。单独100题检索诊断中，2文档限制下V3与旧图同为80/100，4文档限制下V3为84/100、旧图86/100。这项退步也保留。

不是未修改FAST、FullWiki或LENS论文完整复现，也未证明自然语言蕴含、动态更新或全局最优。由于排除了原始问答文本、私人采样排除集和完整模型轨迹，公开包能复现算法、虚构原生机制和已发布数据的统计，不能仅凭此包重建全部历史API响应或核验私人账单。
